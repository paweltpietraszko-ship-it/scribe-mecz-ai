# SCRIBE: THE ONE — Claude Code vs Codex: the models play the shooter themselves

**EN.** This repository holds everything about a match of the third-person arena shooter *SCRIBE: THE ONE* between two AI models, Claude Code and Codex: the referee, the rules the models get, the preparation (trial runs, audits and the fixes that followed them) and, once played, the match itself with everything needed to check it. Status: **preparation**. The match has not been played yet.

**How the models play.** A model cannot steer a shooter at 60 frames a second, so game time stops while a model thinks. The model is the mind: it gives an order in JSON (where to go, behind which block to take cover and against which point, whether to fire, look, sprint, heal, reload, dodge, and for how long the order lasts). The fighter's body carries the order out with the same eyes, hands and legs as the game's own bot on its *Normal* level, the same for both sides: it walks the shortest way, takes the named cover, and aims and fires only at what its eyes see, with a human-like reaction time and aim error. The referee stops the game and asks the model again when something happens: it sees or loses the enemy, is hit, hears a shot, reaches its goal or fails, gets SCRIBE's camping warning, or the order's time is up. The models get only what their fighter could know. They play without tools and without the game's code, only with the rules in [`sedzia/ZASADY_GRACZA.md`](sedzia/ZASADY_GRACZA.md).

**Format.** First to 2 round wins. The players swap start sides after round 1; the side for round 3 comes from the seed. The game's author draws a secret seed, not a player. Its SHA-256 (with a salt), the hashes of every file of the referee and of the game engine, the Node version and installed libraries, the CLI versions and the settings are published **before** the match (`ZOBOWIAZANIE.json`), together with the number of a future round of the public [drand](https://drand.love) randomness beacon. The match seed mixes the secret seed with that round's beacon value, which nobody knows when the commitment is published, so the organiser cannot redraw until a seed suits. The secret seed is published after the match. The commitment also fixes the models of both players; an answer from another model voids the match.

**One commitment, every attempt public.** Each commitment is pushed to this repository (`mecze/<match>/ZOBOWIAZANIE.json`) before its drand round, and the referee does not start before that round. Every attempt stays in `mecze/`, including voided ones.

**A failed model call voids the match** (the game's author's rule, set before the match). A call with no answer at all (no reply within 120 s, or a CLI error) is first asked again with the same prompt, up to 2 more times, while game time stays stopped, so nobody gains from it; every attempt is in the record. A provider limit, a timeout, a CLI error, an answer without proof of the model and of the tool-free setup, or an answer from another model than committed stops the game at once, before the next game step. The record is kept and published with the score at that moment (for example "A led 1:0; match voided after a failed call of B"), and nobody wins. A new match starts from scratch with a new commitment. A wrong answer from a model (not one JSON object, an invalid order) is not a failure: it is rejected and the previous order goes on.

**Pauses between rounds.** A committed match stops after every round, so the rounds can be played in separate usage windows of the models. `--mecz <match> --dalej` replays the record up to the pause with the same checks as `--sprawdz`, requires the same game state at the pause and plays on live.

**Checking a match.** `node sedzia/sedzia.mjs --sprawdz mecze/<match> --gra <game folder>` plays the whole match again without the models. It reads every answer from the models' recorded raw CLI output (`raw/`), and requires every view shown to a model, every order and every game step to be identical to the record. Any edited answer, order, step or file makes it FAIL.

| Folder | What is there |
|---|---|
| [`gra/`](gra/) | the game's code and engine (without models and animations) |
| [`sedzia/`](sedzia/) | the referee (`sedzia.mjs`), the fighter's body (`cialo.js`), the model calls without tools (`gracze.mjs`), the commitment (`zobowiaz.mjs`), the physics replay (`odtworz.mjs`), the rules for the models (`ZASADY_GRACZA.md`) |
| [`przygotowania/`](przygotowania/) | the history of the preparation ([`KRONIKA.md`](przygotowania/KRONIKA.md)), the audit brief, the audit reports and the fixes |
| [`proby/`](proby/) | the trial runs before the audit, with the models' decisions, comments and notes (one full trial round: Codex won in 169 s) |
| `mecze/` | the match package, once played |

**The game engine.** The referee runs the game's own engine without drawing. Its code is in [`gra/`](gra/) (where it comes from: [`gra/ZRODLO.md`](gra/ZRODLO.md)). The game's models and animations are not in this repository, because the animations come from Adobe Mixamo and are not redistributed. `node sedzia/zasoby.mjs` downloads them from the published game and checks their SHA-256.

**Run it yourself** (Node.js 22+): `cd gra && npm ci && cd ..`, then `node sedzia/zasoby.mjs`, then for example `node sedzia/odtworz.mjs proby/3_2026-10-28_runda_probna` (the trial round replayed step for step) or `node sedzia/sedzia.mjs --p0 stub --p1 stub` (a match of two scripted stand-ins, no models).

**PL.** Repozytorium meczu Claude Code kontra Codex w strzelance TPP *SCRIBE: THE ONE*, który modele rozgrywają same: sędzia, zasady dla modeli, przygotowania (próby, audyty i poprawki po nich), a po rozegraniu mecz ze wszystkim, co potrzebne do sprawdzenia. Stan: **przygotowania**, mecz jeszcze się nie odbył. Czas gry stoi, kiedy model myśli. Model wydaje rozkazy, a ciało postaci wykonuje je tymi samymi oczami, rękami i nogami co bot gry na poziomie „Normalny”, jednakowo dla obu. Format: do 2 wygranych rund, zamiana stron po rundzie 1. Awaria wywołania modelu (limit, przekroczony czas, błąd CLI, inny model niż w zobowiązaniu) unieważnia mecz: zapis i stan w tej chwili są publikowane, nikt nie wygrywa, a nowy mecz wymaga nowego zobowiązania. Tajne ziarno losuje autor gry, a jego skrót, odciski plików i numer przyszłej rundy publicznej latarni losowości drand publikujemy przed meczem. Ziarno meczu łączy tajne ziarno z liczbą drand z tej rundy, więc organizator nie może losować do skutku. Sprawdzenie: `node sedzia/sedzia.mjs --sprawdz mecze/<mecz> --gra <folder gry>` rozgrywa mecz od nowa z surowych odpowiedzi modeli i wymaga zgodności każdego kroku. Historia przygotowań: [`przygotowania/KRONIKA.md`](przygotowania/KRONIKA.md). **Wszelkie prawa zastrzeżone**, zob. `LICENSE`.
